# 01. 요구사항 명세

## 배경

AWS SAA-C03 자격증 준비 자료 PDF 5개를 갖고 있으나, PDF 형태로는 학습이 비효율적이다.

- 1019문항을 PDF로 풀면 진도 추적이 불가능하고, 틀린 문제를 다시 찾아가기 어렵다
- 암기 노트와 문제가 분리돼 있어 문제를 풀다 막혔을 때 참조가 끊긴다
- PC와 폰을 오가며 공부하는데 진도가 이어지지 않는다

## 목표

문제 풀이를 중심에 두고, 진도가 기기 간에 이어지는 학습용 웹 애플리케이션을 만든다.

**부차 목표**: NestJS 학습. 이 프로젝트는 NestJS를 실제로 써보는 연습장을 겸한다. 따라서 백엔드가 형식적 껍데기가 아니라 인증·도메인 로직·집계를 실제로 담당해야 한다.

## 비기능 요구사항

**성능**
- 폰 첫 진입에서 문제 목록·필터가 즉시 동작해야 한다 → 전체 문제 데이터(2.7MB)를 받지 않고 인덱스(약 60KB)만으로 처리
- 문제 본문은 100문항 단위 청크로 필요할 때만 받는다

**가용성**
- 개인 학습용이므로 SLA 요구 없음
- 정적 데이터(문제·노트·해부서)는 CDN에서 서빙하므로 백엔드가 죽어도 문제 풀이 자체는 가능해야 한다 (진도 저장만 실패)

**저작권 / 보안** — 조건 자체는 「제약 / 업무 제약」에 있다. 여기는 그래서 지켜야 하는 것만 적는다.
- 데이터는 소유자의 CDN에만 존재한다. CDN은 인증이 없어 URL을 알면 누구나 받을 수 있다 — 경로 비밀(랜덤 프리픽스)과 CORS가 방어선이므로, 실제 경로를 레포·문서·이슈에 적지 않는다

**데이터 보존**
- 해부서 판독 결과는 스크립트로 재현할 수 없는 유일한 산출물이다 (이미지 61장 수동 판독)
- 덮어쓰기 사고를 구조적으로 막기 위해 버전 경로(`v1`, `v2`)를 쓰고 기존 버전을 삭제하지 않는다
- S3 버킷 버저닝을 활성화한다

## 제약

**외부에서 강제된 것만 적는다.** 우리가 고른 것은 제약이 아니라 설계 결정이며 `03-architecture.md` 소관이다.

### 프로젝트 제약

- **개발자 1명.** 리뷰어도 QA도 없다
- **시험일까지의 시간 안에 끝나야 한다.** 이 앱은 시험 준비 도구이므로 개발이 학습을 잠식하면 실패다 (→ 「미해결 사항」의 시간 게이트)

### 업무 제약

- **레포가 public이다**
- **원본 자료가 제3자 저작물이다** (노트 하단 `© 2026 contatto. All rights reserved.`)

이 둘이 데이터 취급 방식 전체를 강제한다 — 어떤 추출 데이터도 git에 커밋하지 않고, 원문을 코드·문서·이슈에 옮기지 않는다.

### 설계 제약

- **백엔드는 NestJS다.** 부차 목표가 NestJS 학습이므로 대체할 수 없다
- **CDN은 기존 보유 자산 `static-cdn.scent-jo.dev`다** (S3 ap-northeast-2 + CloudFront). 이미 보유한 플랫폼이라 새로 고르지 않는다

배포 Vercel · DB Supabase · 프론트 Next.js · pnpm 모노레포는 **제약이 아니라 선택**이다. 예산 제약은 없다 → `03-architecture.md`

## 운영 환경

**대상 기기는 본인의 폰 1대와 PC 1대뿐이다.** 그 밖의 환경은 지원 대상이 아니며, 깨져도 결함으로 치지 않는다.

| | 전제 |
|---|---|
| 브라우저 | 최신 버전의 Chrome(PC·Android)과 Safari(iOS). 구버전 폴리필·트랜스파일 하한을 낮추지 않는다 |
| 최소 화면폭 | **360px**. 이보다 좁은 화면은 검증하지 않는다 |
| 화면 분기 | `compact` / `medium` / `expanded` (`DESIGN.md` Layout) |
| 네트워크 | 이동 중 셀룰러를 포함한다. 인덱스 60KB · 청크 단위 지연 로딩 설계의 근거가 이것이다 |
| 입력 | PC는 키보드가 1급 수단, 폰은 터치. 마우스 전용 동작을 두지 않는다 |

**"오프라인"의 정의**: 완전 오프라인 동작은 지원하지 않는다. 정적 데이터를 CDN에서 받아야 하므로 첫 진입에는 네트워크가 필요하다. 이 문서에서 오프라인이라 부르는 것은 **풀이 도중 백엔드 요청이 실패하는 상태**이며, 그때 진도 저장만 큐잉된다 (`02-features.md`).

아래는 검증된 사실이 아니라 **전제**다. 각 항목이 깨지면 딸린 결정을 다시 열어야 한다.

| 가정 | 여기에 딸린 결정 | 재검토 트리거 |
|---|---|---|

| 원본 PDF 5개가 최종본이다 | 데이터 버전이 `v1`에서 늘지 않는다고 보고 마이그레이션 절차를 두지 않음 | 원본 개정판 입수 |
| 문제은행 블록 구조가 1019문항 내내 균일하다 | 파서가 단일 규칙으로 전수를 처리 | `data:verify`의 정답 개수 분포가 `896/109/14`와 어긋남 |
| CDN 경로 비밀(랜덤 프리픽스)이 유효한 방어선이다 | CDN에 인증을 두지 않음 | 경로 유출 정황 |

## 성공 기준

각 항목은 **무엇을 하면 통과인지**까지 적는다. 판정할 수 없는 기준은 기준이 아니다.

| # | 기준 | 통과 판정 |
|---|---|---|
| 1 | 기기 간 진도가 이어진다 | PC에서 N번 문항을 제출한 뒤 폰에서 `/`에 들어가면 이어풀기가 **N+1번**을 연다 (수동 1회) |
| 2 | 1019문항이 손실·중복 없이 파싱된다 | `pnpm data:verify` 통과 — id 1~1019 연속, 정답 개수 분포 `896/109/14` 일치 포함 (자동, 배포 게이트) |
| 3 | 틀린 문제만 모아 다시 풀 수 있다 | `/review`의 한 문항을 정답으로 다시 풀면 목록에서 사라진다 (수동 + `08-testing.md` 기록 정합성) |
| 4 | 모의고사를 다른 기기에서 이어서 끝낼 수 있다 | 세션을 30문항까지 진행하고 닫은 뒤 다른 기기에서 열어 65문항을 완료해 결과 화면에 도달한다 (수동 1회) |
| 5 | 약한 영역을 식별할 수 있다 | 대시보드가 11개 카테고리 정답률을 낮은 순으로 표시하고, 값이 `05-database.md`의 도출 쿼리 결과와 일치한다 |

## 미해결 사항

결정되지 않은 채 다른 것을 좌우하는 항목. 본문에 숨기지 않는다.

| 항목 | 무엇이 막혀 있나 | 정해지면 |
|---|---|---|
| **시험일** | 미정 | 아래 시간 게이트의 데드라인이 확정된다 |
| **E5 데드라인** | 시험일에 종속 | E6~E8 절단 여부를 판단할 수 있게 된다 |

**시간 게이트**: 이 앱은 시험 준비 도구다 — 개발이 학습을 잠식하면 실패다. 시험일을 기준으로 E5(문제 풀이)가 열려야 하는 데드라인을 두고, 초과가 예상되면 E6~E8을 절단하고 학습을 시작한다.
