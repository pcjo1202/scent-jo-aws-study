# 02. 기능 명세

## 화면 구성

대상 기기와 화면폭 전제는 `01-requirements.md` 「운영 환경」, 폭 분기와 컴포넌트 규격은 `DESIGN.md`를 따른다.


| 경로 | 화면 | 목적 |
|---|---|---|
| `/login` | 로그인 | Google OAuth 버튼 하나 |
| `/` | 대시보드 | 진도 요약, 이어풀기 진입, 약한 영역 확인 |
| `/study` | 순차 풀이 | 1019문항을 순서대로. 필터 적용 가능 |
| `/review` | 오답 복습 | 최근 시도가 오답인 문항만 |
| `/exam` | 모의고사 | 세션 목록 · 새 세션 시작 |
| `/exam/[id]` | 모의고사 진행 | 65문항 일괄 풀이 |

### 공통 골격

로그인 후 화면 8개가 상단 앱바를 물려받고, **네비게이션은 허브-스포크**다 — `/`가 홈이고 상시
네비게이션이 없으며 앱바 좌측 뒤로가기로 `/`에 돌아온다. **`/login`은 예외로 앱바를 두지 않는다** —
비로그인 상태에서 갈 수 있는 화면이 없어 뒤로가기가 가리킬 곳이 없다 (「인증」). 앱바 규격·우측 액션 배정·진행 표시는
`DESIGN.md` 「Components · 공통 헤더·네비게이션」이 정본이다.

### 화면 구성 요소

아래 4화면은 2026-09-02에 배치까지 확정했다 (SJO-44). 나머지 5화면은 이 골격을 물려받되 구성
요소가 아직 미정이다.

| 화면 | 앱바 | 본문 (위→아래) | 하단 액션 |
|---|---|---|---|
| `/` | 제목 좌측 정렬 · 뒤로가기 없음 · 진행 바 없음 | 전체 진도 카드 → 이어풀기 → (진행 중 모의고사 배너) → 오답 진입 행 → 카테고리별 정답률 + 「아직 안 푼 영역 N개」 → 최근 모의고사 3개 → **테마 설정** | 없다 |
| `/study` | `순차 N / 1019` · 우측 `filter_list`(활성 개수 배지) · 진행 바 | (저장 대기 배너) → (적용된 필터 칩) → 지문 → (복수정답 안내) → 선택지 | 이전 · **제출** |
| `/study` 채점 후 | 같음 | (저장 대기 배너) → (적용된 필터 칩) → 결과 배너 → 지문 → (복수정답 안내) → ① 요구사항 → 선택지(해설이 카드 안에서 펼쳐진다) → ④ 등장 서비스 | **다음** |
| `/review` | `오답 복습 N / M` · 우측 `filter_list` · 진행 바 | (저장 대기 배너) → 지문 → (복수정답 안내) → 선택지 | 이전 · **제출** |
| `/review` 채점 후 | 같음 | `/study` 채점 후와 같다 | **다음** |
| `/exam/[id]` | `모의고사 N / 65` · 우측 `grid_view` · 진행 바 | (저장 대기 배너) → 지문 → (복수정답 안내) → 선택지 (**정오를 표시하지 않는다**) | 종료 · 이전 · **다음** |

**적용된 필터 칩과 복수정답 안내는 채점 후에도 남는다.** 필터는 여전히 걸려 있고, 복수정답 안내는
채점 결과를 읽을 때도 「몇 개짜리 문제였나」의 근거가 된다. 사라지는 것은 상태이지 문제의 성질이 아니다.

**배너가 둘 뜨면 저장 대기가 위다.** 채점 후 화면에서 「저장 대기 N건」과 결과 배너가 함께 뜰 수 있는데,
저장 대기는 화면 전체에 걸리는 시스템 상태이고 결과 배너는 이 문제 하나의 판정이라 범위가 넓은 쪽이
위다 — 본문 첫 블록은 언제나 상태 배너다 (`DESIGN.md` 「상태 배너 · 어디에 놓이나」).

**문제 번호는 앱바가 전담한다.** 「표시 요소」의 *문항 번호, 전체 진행 위치*가 앱바 제목의
`순차 12 / 1019`다. 본문에 다시 적지 않는다.

**복수정답 안내(「정답 2개를 고르세요」)는 세 화면 모두에 뜬다.** 복수정답 문항일 때만 나오고,
선택지 목록 바로 위 8px다 (`DESIGN.md` 「단일정답 / 복수정답」). 123문항이 복수정답이라 예외가 아니다.

**적용된 필터 칩은 눌러도 지워지지 않는다.** 「Icons」 세트에 `close`가 없고, 해제는 앱바 우측
`filter_list`로 패널을 열어서 한다. 칩은 지금 무엇이 걸려 있는지를 보여주는 표시다.

`/review`의 분모 `M`은 **화면에 들어온 시점에 고정한다.** 맞힐 때마다 줄면 `3 / 27`이 풀 때마다
흔들려 어디까지 왔는지를 알 수 없다 (SJO-30 「복습 세트: 진입 시 고정 vs 실시간 갱신」의 화면 쪽 답).

**테마 설정은 `/` 대시보드 맨 아래에 둔다.** 기본값이 `system`이라 OS가 밤낮을 자동으로 바꿔 주므로
수동 전환은 드문 조작이고, 그 드문 조작에 9화면 전부의 앱바 우측을 상시 내주면 `/study`의 필터
버튼이 갈 곳을 잃는다 (SJO-30 「테마 토글의 화면상 위치」 해소).

`expanded`에서 달라지는 것은 **좌측 320px 「화면 보조 패널」** 하나다 — `/study`·`/review`는 필터,
`/exam/[id]`는 문제 이동 그리드, `/`는 없음. `compact`에서 앱바 우측 버튼이 열던 전체 화면 시트가
`expanded`에서는 그 상시 패널이므로 **우측 버튼이 사라진다.**

## 공통: 문제 풀이 컴포넌트

`/study`, `/review`, `/exam/[id]`가 모두 이 컴포넌트를 쓴다. 모드에 따라 채점 시점만 달라진다.

### 표시 요소

- 문항 번호, 전체 진행 위치
- 지문
- 선택지 A~F — 문항마다 4~6개다 (`01-requirements.md` 「문제은행」)
- **복수정답 문항이면 "정답 N개를 고르세요"를 명시**한다. `N`은 그 문항의 정답 개수이고 고정값이 아니다 — 인덱스의 `answerCount`를 그대로 넣는다. 실제 시험도 `Choose TWO`로 알려주므로 숨기는 것은 시험 환경과 다르다
- 제출 버튼 — **즉시 채점 모드에만 있다.** `/exam/[id]`는 「다음」으로 넘어가며 답이 저장된다 (「모드별 차이」)

### 선택 규칙

정답 개수가 조작 방식을 결정한다.

| 문항 | 조작 | 초과 선택 |
|---|---|---|
| 단일정답 | **교체** — 다른 선택지를 고르면 이전 선택이 풀린다 | 발생하지 않는다 |
| 복수정답 | 토글 | **막는다** — 필요 개수를 채우면 나머지 선택지를 비활성화한다 |

제출 버튼은 필요 개수를 **정확히** 채웠을 때만 활성화된다. 부족도 초과도 정상 경로로는 서버에 도달하지 않는다.

서버는 초과 선택을 오답으로 채점한다 (`08-testing.md`). 화면이 막는데도 판정을 서버에 남기는 이유는 오프라인 큐 재전송 경로가 화면을 거치지 않기 때문이다.

### 채점 후 표시 (즉시 채점 모드)

**해설은 화면 하단에 쌓이지 않는다. 각 선택지 카드 안에서 펼쳐진다** (`DESIGN.md` 「해설 블록」).

1. 정오 여부 — 결과 배너
2. 지문 (그대로 남는다)
3. **요구사항/조건** — 원본에 있는 불릿. 문제를 조건으로 분해한 것이라 해설보다 먼저 본다. 선택지 위에 둔다
4. 선택지 — **정답 선택지 안에 정답 해설, 각 오답 선택지 안에 그 선택지의 오답 해설**이 들어간다. 내가 고른 오답과 정답만 기본 펼침이고 나머지는 접힌다
5. **등장 서비스 칩** — 이 문항에 매칭된 서비스명. 누르면 해당 한줄노트가 인라인으로 펼쳐진다

5번이 이 앱의 핵심 가치다. 문제를 풀다 "EFS가 뭐였지"에서 흐름이 끊기지 않게 한다.

해설을 선택지 안에 넣는 이유는 **오답 해설이 선택지를 문자로 참조**하기 때문이다(`B. 각 부서에…`
형식). 따로 쌓아 두면 눈이 위아래를 오간다 (2026-09-02, SJO-44).

### 키보드 조작 (PC)

1019문항을 마우스로만 푸는 것은 현실적이지 않다.

| 키 | 동작 |
|---|---|
| `1`~`6` | 선택지 A~F 선택 — 숫자는 키가 아니라 **순서**에 붙는다 (위 「선택 규칙」을 따른다) |
| `Enter` | 제출 / 다음 |
| `←` `→` | 이전 / 다음 문항 |
| `?` | 단축키 도움말 |

### 관련 해부서 링크

문항의 카테고리로 PART 2의 서비스군 절을 연결한다. 자동 매핑이라 정확하지 않을 수 있으므로 **"관련 있을 수 있는 절"** 로 약하게 제시한다. 단정하지 않는다.

### 모드별 차이

| 모드 | 제출 후 | 채점 시점 |
|---|---|---|
| 순차 (`/study`) | 즉시 채점 표시 | 문항별 |
| 오답 복습 (`/review`) | 즉시 채점 표시 | 문항별 |
| 모의고사 (`/exam/[id]`) | 「다음」으로 넘어가며 답이 저장된다. 정답을 숨긴다 | 세션 종료 시 일괄 |

```

```

## `/study` 순차 풀이

**첫 문항에서 「이전」은 비활성이고 숨기지 않는다. 마지막 문항(1019)에서 「다음」은 완주 상태로 보낸다**
(「빈 상태」의 `/study` 행). 비활성 처리는 `DESIGN.md` 「하단 액션의 버튼 배치」.

- 진행 포인터(`last_question_id`)의 다음 문항부터 시작한다
- 답을 제출하면 포인터가 갱신된다
- 이전 문항으로 되돌아갈 수 있다. 되돌아가서 다시 풀면 시도가 새로 기록되지만 포인터는 뒤로 가지 않는다

### 필터

| 필터 | 값 | 출처 |
|---|---|---|
| 카테고리 | 11개 (컴퓨트·스토리지·DB·네트워크·보안·메시징·분석·모니터링·운영·AI/ML·마이그레이션) | 인덱스 |
| 서비스 | 202개, 검색형 선택 | 인덱스 |
| 정답 개수 | 단일 / 복수 | 인덱스 |
| 풀이 상태 | 안 푼 것 / 오답 / 정답 | 서버 |

**네 필터 모두 다중 선택이다.** 같은 필터 안은 OR(컴퓨트 *또는* 스토리지), 필터 간은 AND. 아무것도 고르지 않은 것과 전부 고른 것은 같다 — 둘 다 필터 없음이다.

규칙을 하나로 둔 이유는 예외가 생기는 순간 화면과 구현이 각자 그 예외를 기억해야 하기 때문이다. "단일정답 + 복수정답"처럼 전체와 같아지는 조합이 생기지만, 그건 무의미할 뿐 틀리지 않는다 (2026-09-02, SJO-44).

앞의 셋은 클라이언트가 인덱스(60KB)만으로 처리한다. 풀이 상태만 서버 조회가 필요하다.

필터를 걸면 해당 부분집합 안에서 순차 진행한다. 전체 진도 포인터와는 별개로 동작하며, 필터를 건 상태의 진행 위치는 저장하지 않는다.

**앱바 제목의 분모도 부분집합을 따른다** — 27문제로 좁혔으면 `순차 3 / 27`이고 진행 바도 그 기준이다.
전체 진도(`/ 1019`)를 계속 보여주면 지금 몇 개 남았는지를 화면에서 알 수 없다. 필터가 없을 때만
`순차 N / 1019`다.

필터 모드의 제출은 `advancesPointer: false`로 보내 전체 진도 포인터를 건드리지 않는다 (`05-database.md`).

## `/review` 오답 복습

- 각 문항의 **가장 최근 시도가 오답**인 것만 모은다
- 다시 풀어서 맞히면 목록에서 빠진다
- 카테고리 필터를 걸 수 있다
- 오답 목록의 정렬은 문항 번호순 (틀린 시각순은 v1 제외)

## `/exam` 모의고사

### 세션 생성

- 1019문항에서 **65문항을 무작위 추첨**한다
- 추첨 결과는 세션 생성 시점에 고정된다. 중간에 바뀌지 않는다
- 추첨은 균등 무작위다. 카테고리 비율을 실제 시험에 맞추는 가중 추첨은 v1 제외 (원본에 도메인 비중 정보가 없음)
- **안 푼 문항 우선** 옵션을 제공한다 — 순차 학습으로 이미 본 문항이 재출제되는 기풀이 편향을 줄인다
- **진행 중인 세션은 사용자당 최대 1개다.** DB 제약으로 보장한다
- 진행 중 세션이 있는 상태에서 새 세션을 시도하면, 기존 세션을 **이어가거나 포기**하도록 안내한다. 포기하면 세션과 그 답안이 삭제된다

### 진행

- 문항 간 자유롭게 이동할 수 있다
- **「다음」은 항상 활성이다.** 답을 고르지 않아도 넘어간다 — 미응답 문항이 허용되고(「종료 / 결과」)
  건너뛴 뒤 나중에 돌아올 수 있어야 한다. 「선택 규칙」의 *"제출 버튼은 필요 개수를 정확히 채웠을 때만
  활성화된다"* 는 즉시 채점 모드(`/study`·`/review`)의 「제출」 규칙이고, 이 화면에는 제출 버튼이 없다
- **마지막(65) 문항에서 「다음」은 「종료」로 바뀐다.** 주 버튼 자리를 그대로 쓰고, 누르면 종료
  확인 다이얼로그가 뜬다. 하단의 보조 「종료」는 그대로 있다 — 어느 문항에서든 끝낼 수 있다
- 답은 제출 즉시 서버에 기록되지만 정오는 표시하지 않는다
- 답을 바꿀 수 있다. 마지막 답이 채점 대상이다
- **중간에 나가도 세션이 유지된다.** 다른 기기에서 이어서 진행할 수 있다
- 진행 위치(`cursor`)와 답안이 서버에 있으므로 기기가 바뀌어도 그대로다

### 종료 / 결과

- 사용자가 하단의 「종료」를 누르거나, 마지막(65) 문항에서 「종료」로 바뀐 주 버튼을 누른다. 둘 다 확인 다이얼로그를 거친다
- 미응답 문항은 오답 처리한다
- 결과 화면: 점수(65점 만점), 카테고리별 정오, 문항별 리뷰(정답·해설·오답 해설 전체 공개)
- 결과 화면에 **기풀이 문항 수(N/65)**를 표기한다 — 점수의 상방 편향을 숨기지 않는다
- 종료된 세션은 결과를 다시 볼 수 있다. `GET /exams/:id`가 종료된 세션에 대해 채점 결과를 함께 돌려준다

### 시간 제한

**v1에서는 두지 않는다.** 실제 시험은 130분이지만, 타이머는 학습보다 시험 리허설 기능이다. 세션에 `started_at`이 있으므로 나중에 추가할 수 있다.

## 빈 상태

데이터가 없을 때 무엇을 보여줄지 정한다. 빈 화면을 그대로 두지 않는다.

| 화면 | 조건 | 표시 |
|---|---|---|
| `/` 대시보드 | 시도 0건 | 진도 `0 / 1019`와 "첫 문제 풀기". 정답률 막대는 그리지 않는다 — "아직 안 푼 영역 N개" 줄도 함께 뺀다(11개 전부라 정보가 없다). 오답 진입 행·최근 모의고사·이어가기 배너도 0건이면 그리지 않는다 |
| `/` 정답률 막대 | 한 번도 안 푼 카테고리 | **정렬에서 제외**하고 아래에 "아직 안 푼 영역 N개"로 따로 표기 |
| `/study` | 1019문항을 다 풂 | **`/study` 화면**에 "전체 완주"와 `/review`·`/exam` 유도. `/` 대시보드의 이어풀기 버튼도 함께 "전체 완주"로 바뀐다 |
| `/study` 필터 | 결과 0건 | 적용된 필터 칩은 **상단에 남기고**, 그 아래 영역에 "조건에 맞는 문제 없음" + 「필터 해제」. 무엇 때문에 0건인지가 보여야 해제할지 고칠지를 정한다 |
| `/review` | 오답 0건 | "복습할 오답이 없다" + 주 버튼 「순차 풀이」(→ `/study`). **실패가 아니므로 경고 색을 쓰지 않는다** |
| `/exam` | 세션 0건 | 목록을 감추고 "새 모의고사 시작"만 |
| `/notes` 검색 | 결과 0건 | "검색 결과 없음" |

**안 푼 카테고리를 정답률 막대에서 빼는 이유**: `GET /stats`는 `solved`가 0이면 `accuracy`를 0으로 돌려준다 (`05-database.md`). 막대는 낮은 순 정렬이므로, 그대로 그리면 **안 푼 카테고리가 항상 맨 위를 차지해 실제로 약한 영역을 가린다.** 0%와 "아직 안 풂"은 다른 상태다.

## 인증

- Google OAuth 하나만 제공한다. 매직링크는 메일 발송 인프라가 필요해 개인 학습앱에 과하다
- 비로그인 상태로는 아무것도 하지 않는다. `/login`으로 보낸다
- 세션 만료 시 조용히 갱신하고, 실패하면 `/login`으로 보낸다
- 로그인 자체는 아무 구글 계정이나 가능하다. 대신 **API가 허용된 이메일(`ALLOWED_EMAIL`) 외에는 전부 403**을 준다 — 접근 통제는 서버가 한다

## 장애 및 오류 처리

### 백엔드 요청 실패 (오프라인 큐)

정적 데이터는 CDN에 있으므로 백엔드가 죽어도 **문제를 읽고 푸는 것 자체는 동작한다.** 실패하는 것은 진도 저장뿐이다.

- 답안 제출은 **낙관적 UI**로 처리한다. 화면은 즉시 진행한다
- 실패한 제출은 `localStorage` 큐에 쌓고 다음 요청에 함께 재전송한다 (`POST /attempts/batch`)
- 큐 항목은 클라이언트 발생 시각(`answeredAt`)을 가지며, 서버가 이를 `created_at`으로 기록한다 — 재전송이 늦어도 "최신 시도" 판정이 뒤집히지 않는다
- 재시도는 네트워크 오류만 한다. 4xx로 거절된 항목(예: 그 사이 다른 기기에서 세션 삭제)은 큐에서 버린다
- 큐에 쌓인 게 있으면 상단에 "저장 대기 N건"을 표시한다. 큐가 비면 표시를 지운다

### 정적 데이터(CDN) 실패

CDN은 백엔드보다 상위 의존이다. **`manifest.json`을 못 받으면 앱이 아무것도 하지 못한다** — 이 앱의 유일한 단일 실패 지점이다.

| 실패 | 영향 범위 | 처리 |
|---|---|---|
| `manifest.json` | 앱 전체 | 전체 화면 오류 + 재시도. 다른 화면으로 넘기지 않는다 |
| `index.json` | 목록·필터·추첨 | 위와 같다. 인덱스 없이 성립하는 화면이 없다 |
| `chunk-NNN.json` | 해당 100문항 | 그 문항 위치에서 오류 + 재시도. 이미 받은 청크는 계속 풀린다 |
| 해부서 이미지 | `/anatomy`만 | 해당 페이지에 대체 표시. optional 자산이므로 다른 화면은 영향 없다 (`04-data-model.md`) |

manifest와 index는 immutable이라 한 번 받으면 브라우저 캐시가 사실상 재시도를 대신한다.

### API 오류의 화면 표현

`05-database.md`가 정의한 응답이 화면에서 무엇이 되는가.

| 응답 | 상황 | 화면 |
|---|---|---|
| 401 | 세션 만료 | 조용히 갱신을 시도하고, 실패하면 `/login` |
| 403 | 허용되지 않은 계정 | 로그아웃하고 "소유자 전용"을 알린다. 재시도를 유도하지 않는다 |
| 404 `GET /exams/:id` | 없거나 남의 세션 | `/exam` 목록으로 돌려보내고 "세션을 찾을 수 없다" |
| 409 `POST /exams` | 진행 중 세션 존재 | 이어가기 / 포기 선택 (「세션 생성」) |
| 409 `finish` — `content_version` 불일치 | 진행 중에 문제 데이터가 새 버전으로 교체됨 | **채점하지 않는다.** "문제 데이터가 갱신되어 이 세션은 채점할 수 없다"를 알리고 포기만 제공한다 |
| 409 `DELETE /exams/:id` | 이미 종료된 세션 | 결과 화면으로 보낸다 |
| 400 | 범위 밖 `questionId` · 선택지 키 불일치 | 정상 경로에서는 나오지 않는다. 나왔다면 큐가 오염된 것이므로 **해당 항목을 버리고** "저장하지 못한 기록 N건"만 알린다 |
| 5xx · 네트워크 | 백엔드 장애 | 위 「백엔드 요청 실패」의 큐 경로 |

**`content_version` 409가 가장 아픈 경로다.** 65문항을 푼 세션이 통째로 무효가 된다. v1은 이를 감수하되, **데이터를 새 버전으로 올리기 전에 진행 중 세션이 없는지 확인**해 운영으로 회피한다.

## 기기 간 동기화 정책

사용자가 1명이므로 정교한 충돌 해결을 두지 않는다.

| 데이터 | 정책 |
|---|---|
| 시도 기록 | append-only. 충돌이 발생하지 않는다 |
| 진행 포인터 | 단조 증가 (`greatest`) — 뒤로 가지 않는다 |
| 모의고사 세션 | 서버가 단일 원본. 클라이언트는 매번 서버 상태를 읽는다 |

두 기기에서 동시에 같은 모의고사를 진행하는 것은 막지 않는다. 마지막 답이 남는다.
