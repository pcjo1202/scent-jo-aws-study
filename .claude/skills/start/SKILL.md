# /start — 이슈 착수

인자: 이슈 ID (예: `SJO-2`). 없으면 로드맵 순서상 다음 이슈를 제안한다.

0. **에픽 정밀화 게이트** — 이 이슈가 속한 에픽에서 처음 착수하는 이슈면, 그 에픽의 모든 이슈를 최신 docs와 대조한다: ① 기준 명세 절 명시 ② 이슈 생성 이후의 docs 변경(결정 사항)을 체크리스트에 반영 ③ SJO-30의 해당 에픽 미결정 해소 ④ DoD가 실행 가능한 verify인지 확인. 정밀화 결과를 첫 이슈 코멘트로 남긴다.
1. **게이트** — In Progress 이슈가 이미 2개면 착수하지 않는다 (하나를 `/done`으로 닫거나 사용자에게 묻는다). 이슈의 blocked-by가 모두 Done인지 확인, 아니면 중단하고 보고.
2. **할당** — 이슈를 `In Progress` + `me`로 갱신한다.
3. **컨텍스트** — 이슈의 목표·완료 정의·체크리스트와, 이슈가 참조하는 docs/ 절을 읽는다. SJO-30(명세 공백)에 이 이슈와 겹치는 미결정 항목이 있는지 확인한다.
4. **계획** — 체크리스트를 실행 순서로 정렬하고, **태스크마다 `verify: <확인 명령/방법>`을 명시**한다. verify를 쓸 수 없는 태스크는 태스크가 아니라 모호함이다 — 3번으로 돌아가 명세를 해소한다 (결정은 해당 doc에 반영 후 SJO-30 체크).
5. **기록** — 완성된 계획을 이슈 코멘트로 남긴다. 세션이 중단되면 다음 세션은 이 코멘트에서 재개한다.
6. **확인** — 3단계 이상 계획이면 사용자에게 한 번 보이고 시작한다.

## gotchas

- 체크리스트 순서가 의존 순서와 다를 수 있다 — 그대로 따르지 말고 정렬부터
- docs/가 SJO-30의 미결정 항목을 참조하면 그 부분은 코딩 금지 — 결정 먼저
- "간단하니까 계획 없이 바로 코딩"이 가장 흔한 실패 경로다 — verify 없는 착수 금지
- 이슈는 docs보다 먼저 썩는다 — 정밀화 게이트를 건너뛰면 낡은 체크리스트대로 만들게 된다
